# 浏览器状态采集、页面重建与防遮挡构图规范

本文件规范如何从真实运行中的网页采集视觉与结构基线，并在 `.sketch` 中高保真重建应用页面、入口组合图与数据看板。

---

## 1. 浏览器采集与 DOM / A11y 自省

### 会话与窗口绑定
- **复用已登录会话**：当用户要求复用现有 Chrome 登录态时，先列出窗口识别目标 PID 与 Window ID 并将采集固定到该窗口；改变任何页面状态前先核验当前活动标签页与 URL。非明确要求复用原标签页的展示变更，可使用独立窗口/托管配置打开精确 URL，任务结束后仅关闭新建窗口。
- **采集方式选型**：
  - 仅需可逆视觉状态切换且不依赖 DOM 样式时，可使用带标注控件的截图模式 + 完整可访问性树（Accessibility Tree）获取标签与边界；**但必须以实际截图为准判断页面真实可见文字**（无障碍标签常包含已被省略号截断隐藏的字符）。
  - 需要精确 DOM 样式与坐标时，复用单条经批准的持久 CDP WebSocket 会话（可经私有 Unix Socket 桥接），全过程保持已核验的目标会话一致。
- **热身截图（Warm-up Capture）**：切换路由或调整视口后，先拍一张热身图等待布局观察器（Layout Observers）稳定，再执行 DOM 提取与最终截图；否则自定义容器可能误报物理窗口高度而截图使用的是模拟视口尺寸。

### DOM 与色彩精确提取
- **穿透 Shadow Root**：现代应用或自定义工作区内容可能渲染在 `div` 的 Shadow Root 内（此时 `document.body.innerText` 与 `Page.getFrameTree` 仅暴露外层导航），提取脚本必须递归遍历 Shadow DOM。
- **按绘制顺序（Paint Order）提取**：提取文本行的 Range 矩形、计算颜色、渐变、四边边框、圆角、裁剪（clipping）、透明度、内联 SVG 颜色/描边及图片边界；保持原生文字层与图像素材彻底分离。
- **色彩空间校准（Display P3 → sRGB）**：macOS Chrome 截屏常携带 Display P3 色域；采样像素颜色前必须用 Pillow `ImageCms` 转为 **sRGB**，切勿把原始 P3 数值直接当 sRGB 写入 Sketch。
- **可见区域内采样**：对被裁剪元素，只在元素可见矩形与截图内部采样；向图像边缘钳位采样会把页面背景色混入渐变。
- **状态记录与复原**：为每个采集态保存清单（源 URL、时间戳、视口、PNG 路径、DOM/A11y 快照路径）；遇到超时先留存当前原生窗口截图再重试。任务完成后，务必将原标签页的菜单状态、路由、视口与活动标签页恢复原样。

## 2. 应用页面与组件重建

1. **精准裁剪与去噪**：
   - 组件级插图仅裁剪到目标组件；全页插图须将应用视口与浏览器外框剥离并保持原始纵横比。
   - 仔细区分应用自身控件与浏览器插件/系统浮层，绝不把浏览器扩展角标画进原型。
   - 核查应用清单与真实路由，明确标记已下线的旧功能，绝不把旧 mock 翻译一下冒充当前真实页面。
2. **范围受控的内容微调**：
   - 内容调整严格限定在指定组件内；例如对应用切换器应用白名单后，同步重算展示的已安装应用计数；若应用改名，同步更新选择器与侧边栏匹配标题，同时保留底层导航文案与层级不变。
3. **可编辑分层**：
   - 按功能区对导航、文本、输入控件、图标与背景做图层分组；优先复用真实静态资源，任何近似替代的 Logo、图标或头像须在交付说明中披露。

## 3. 入口导航图特殊技巧：展开菜单防遮挡错位排布

> 典型场景（`TYPE: entry-screenshot`）：需要在同一张入口图中同时展示“展开后的应用切换下拉菜单”与“左侧导航栏里的目标菜单项”，但真实界面中下拉菜单展开后会盖住下方导航。

按以下 5 步精确处理：
1. **同视口双态采集**：在同一视口尺寸下，分别采集菜单**展开态**与**收起态**。
2. **素材分工**：用展开态还原顶部切换器与下拉菜单，用收起态还原被遮挡的下方导航菜单。
3. **流式置入与高度测算**：保持原侧边栏宽度不变，将展开菜单直接排布在触发器下方的正常垂直流中；按目标应用白名单更新菜单条目后，实测展开菜单的最终高度。
4. **统一下移与画板延展**：将下方原有导航分组以**统一的垂直偏移量**整体下移（保持源行距与水平坐标完全不变），同步拉高画板总高度，确保底部账号栏完整可见。
5. **红框标注与视觉复核**：用清晰圆角红框标出各级入口，在导出 PNG 中逐一核对：单行省略描述仍为单行、展开菜单底边与下方第一个分组标题留足清晰空隙、底部账号区无裁切。

## 4. 大屏看板重建与一致脱敏数据集（Dashboard）

1. **画布边界纯净化**：识别实时编辑器中的看板画布边界及配置尺寸，按原生纵横比重建；彻底剔除浏览器外框、编辑器面板、标尺、选中手柄与画布外杂散对象。若用户提供了早期草图用于补齐缺失语义或图表结构，仅借鉴其内容与口径语义，**不得用旧草图尺寸替代当前真实画布几何**。
2. **单一自洽脱敏数据集（授权替换示例数据时必填）**：
   - 渲染前先定义一份统一数据集，卡片数值、漏斗标签、趋势终点、排行条与价值计算全部由该数据集派生。
   - 已确认结论与推断结论保持互斥，其总和与汇总解决率一致；重开率等指标须有明确分母与统计窗口。
   - 运维看板必须跨组件数学闭环：**`Today` / `7 days` / `This month` 嵌套时间窗**逻辑自洽、日柱状图各日加总等于月度卡片总值、受影响服务去重数与明细列表行数严格一致。
   - 保留原界面公式语义并显式标注可配置基线（如 `SAMPLE DATA` 徽标与可配置 Baseline）；用合理的示例数据替代失真占位符，而非仅仅隐藏负数。
   - 英文交付物须将所有标签、图例、主题与动态条目完整译为英文，同时保留专有产品名。
3. **矢量优先**：普通折线图、柱状图、进度条与徽标一律重建为原生形状/矢量路径与独立文字层，仅对照片或不受支持的内嵌画布保留位图。
