# 已有 `.sketch` 精准裁框、归档微调与壳层保护规范

本文件用于处理两类高频维护任务：
1. **画板裁框（Frame Fitting）**：基于用户已手改的 `.sketch` 文件，仅收紧或调整画板边界并重导出 PNG；
2. **壳层刷新（Shell-Only Refresh）**：仅更新导航壳层/页眉/控件，同时完好锁定并保留内嵌产品的原始图像区域。

---

## 1. 已有 `.sketch` 精准裁框与重导出（不动其它任何图层）

1. **锁定最新基线并留证**：
   - 找到用户最新保存的版本（含用户在先前交付稿上的就地修改）；若同时存在上一版自动生成稿与用户手改稿，先做比对并记录选定基线的文件哈希（SHA-256）。
   - 修改前先导出当前画板作为视觉基线：
     ```bash
     sketchtool export artboards INPUT.sketch --output=DIR --formats=png --scales=1
     ```
2. **读取目标画板并按“有意可见边界”定框**：
   - 解析归档内的 `document.json` → `pages[*]._ref` → 对应页面 JSON，以及 `meta.json`，按画板名或图层 ID 定位目标 Frame。
   - 贴合用户实际调整出的**有意可见边界**（例如用户已拉窄或拉短的侧边栏背景底框）；若仅高度多余，则严格保留原有的宽度与内边距。
   - **禁止直接对所有子组（Group）的 `frame` 取并集**：历史残留的 Group 边界常保留着已删除行占过的空间，且投影也会向画布外溢出。
3. **归档级精准编辑（输出新版本副本，绝不改原文件）**：
   - 只修改目标画板 Frame 的坐标或宽高，其余所有 ZIP 条目原样保留。
   - **Python `zipfile` 关键避坑**：通过 `zipfile.ZipFile.writestr()` 回写条目时，必须传入 `copy(info)`（`from copy import copy`），因为 `writestr` 会原地篡改传入的 `ZipInfo` 元数据，导致后续读取原归档出错。
4. **重导出、刷新内嵌预览与反向比对验证**：
   - 对新版本 `.sketch` 执行 `sketchtool export artboards ... --formats=png --scales=1` 导出 PNG。
   - 若为单画板文件且内嵌缩略图已过期，用新导出的 PNG 同步刷新归档内的 `previews/preview.png`。
   - **三层核验**：
     1. **ZIP 与图层零污染验证**：反向还原仅被修改的 Frame 数值后，其余图层 JSON 必须与原版 100% 字节/结构一致；
     2. **像素级裁切比对**：纯裁框改动时，将新 PNG 与原图对应裁剪区逐像素比对（仅允许极少量 1 级抗锯齿差异），并目视检查裁切边缘无文字/边框被误切；
     3. **原文件哈希复核**：交付前再次校验用户原始 `.sketch` 文件哈希未发生任何变更。

---

## 2. 壳层刷新与内嵌区域锁定保护（Shell-Only Updates）

当任务明确为“仅刷新外围导航/壳层，不改动内嵌子产品工作流”时：

1. **严格剔除范围外任务**：即使规格文档中同时描述了壳层和内嵌产品流程，也要把内嵌产品内部改动移出本次工作计划。
2. **锁定内嵌原始图像区**：重建外围导航、顶部栏、全局控件与布局，将内嵌产品的原始界面区域作为**锁定图像层（Locked Layer）**完整保留。
3. **裁剪坐标与像素哈希留痕**：记录该内嵌区域的精确裁剪矩形与像素哈希；未经授权，仅允许对其做整体等比定位摆放，禁止篡改内部像素或伪造运行态。
4. **区分真实失败与壳层合成**：若真实运行环境中的 iframe 加载失败，须保留该失败截图作为运行态证据；若经授权将旧版正常内嵌画面合成进新版壳层，须在内部记录来源溯源，**绝不拿失败画面顶替正常流程插图，也不宣称该合成图证明了运行期嵌入已通**。
