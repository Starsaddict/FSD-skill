# FSD 图表选型思路与 5 类高频原型骨架

在动笔写 SVG 之前，先回答一个问题：**这张图在 FSD 里要帮读者看懂什么？** 不要把所有业务都硬塞进三层横泳道——按业务本质从以下 5 类经过实战验证的原型中选用最契合的一种。

---

## 1. 选型决策矩阵

| 如果你要表达的是…… | 首选原型 | 典型落位（FSD 章节） |
|---|---|---|
| 多角色、AI 代理与外部系统之间的端到端协同全景 | **原型 A：端到端跨角色泳道图** | `2.1.1 User Journey` |
| 定时/事件触发的数据处理管线 + 失败队列与人工重试闭环 | **原型 B：管线 + 异常重试泳道图** | 后台采集、标准化、同步步骤 |
| 单个业务对象的全生命周期、多条终止路径与跨系统影响 | **原型 C：无泳道分阶段状态迁移图** | 状态机、队列流转、关闭/过期规则 |
| 多条件分支决策 + 平行评估标准 / 排除红线 / 实体关系 | **原型 D：决策流 + 侧边规则栏 / 底部关系面板** | 规则判定、路由分诊、上下文富化 |
| 多个独立计时器、重置规则、固定上限与时间戳不可混用原则 | **原型 E：多独立时间轴 + 底部不变式横幅** | 时间窗口与超时边界说明 |

> **对象关系图特别提醒**：若仅表达实体层级/关联关系（如 CMDB 1 度关系），不要强套泳道；将共同根对象置顶、直接关联对象并排、下游对象置于父节点下方，正交连线从各边缘分流并标注关系名（参考原型 D 底部面板）。

---

## 2. 五类原型结构骨架

### 原型 A：端到端跨角色泳道图（End-to-End Swimlane Journey）
- **布局**：顶部总标题+副标题 → 编号阶段列头（`01` ~ `05`）+ 贯穿竖向虚线 → 3 条水平泳道（上：暖色 `Human Roles`；中：蓝色 `Agents / Core System`；下：绿色 `Systems & Data`）。
- **内容克制**：每张卡片严格控制 `1 行粗体标题 + 2~3 条精炼 bullet`；泳道间交互用垂直正交线 + 胶囊 Pill 标签标明传递物（如 `Config / Retry`、`Active queues`、`Callback`）。
- **线型**：同步/主交互用实线，异步回调/人工干预回流用虚线。

### 原型 B：管线 + 异常重试泳道图（Pipeline with Exception & Retry Swimlane）
- **布局**：编号步骤列（`01` ~ `04`）× 3 条职责泳道：
  - 上层（蓝色）：触发与输入源（如 `Scheduler & Source`）—— 采集失败用**红色卡**就地留在同泳道右侧，清晰标明游标不推进；
  - 中层（绿色）：核心处理引擎（如 `Conversion Engine`）—— 正常产出向右流出；
  - 底层（暖色）：`Exception & Retry` —— 红色失败卡向右接暖色人工重试卡，虚线向上回到中层表 `Retry succeeds`，虚线绕底部回环表 `Retry fails (attempt logged)`。

### 原型 C：无泳道分阶段状态迁移图（Lifecycle & State Transitions）
- **布局**：取消横向泳道，保留编号阶段列（`01` ~ `04`）与竖向虚线分隔，让读者的视线纯按状态推进阅读：
  - 左侧列：候选/输入状态（暖色虚线框或蓝色输入卡）+ 红色拒绝出口；
  - 中间列：活跃状态（蓝色卡）+ 多条分流/终止路径卡（按语义着色：超时用暖色、正常人工/合并用绿色、外部同步用蓝色）；可用**暖色虚线卡**就地补充重要失败兜底规则（不抢主流程视线）；
  - 右侧列：**红色实线不可逆终态卡**（如 `Expired` / `Closed`）+ 虚线向下接绿色收口处置卡（如 `Final Dispositions`）。

### 原型 D：决策流 + 侧边规则栏 / 底部关系面板
两种实用复合版式，解决“既要看流程分支、又要看判定依据”的排版难题：
- **左右分栏型（决策流 + 右侧平行规则栏）**：
  - 左侧约 2/3 宽：竖向顺流决策主干（蓝色普通矩形判断卡 + 绿色/蓝色/暖色结果卡 + 红色超时终态卡 + 侧边虚线重评估回环）；
  - 中间一条贯穿竖虚线；
  - 右侧约 1/3 宽：纵向堆叠等价评估规则卡（蓝色），最底端放一张**红色排除/互斥红线卡**（如 `Exclusions & Exclusivity Rules`）。
- **上下分区型（主流程 + 底部参考关系面板）**：
  - 上半区：4 阶段主分流（正常确认走绿色、降级不阻塞走暖色 → 蓝色继续推进）；
  - 下半区：浅蓝灰容器（`#f4f7fb` + `#9bb9de` 边）内画简明层级关系示意图（顶层蓝色根实体 → 正交分流带标签 → 下排绿色关联实体卡）。

### 原型 E：多独立时间轴 + 底部不变式横幅（Multi-Timeline & Integrity）
- **布局**：3 条纵向堆叠的独立圆角主题面板（依次蓝 / 暖 / 绿底色），明确视觉隔离“彼此独立、互不叠加”：
  - 每个面板左侧 2/3：主题色横轴 + 实心主题色时间节点圆点 + 区间色块（滑动重置延长段用**同色虚线边框**表示，超时终止段用**红色实线块**表示）；
  - 每个面板右侧 1/3：同色系 `Key Boundary Rules` 卡片，列出 3~4 条核心边界；
  - 最底部：浅蓝灰容器横幅（`#f4f7fb` + `#7799c2` 边），内嵌等宽白卡（`#ffffff` + `#b3cbe6` 边）并排列出彼此不可替代的独立时间戳定义。

## 3. 对接 `fsd-writer` 的 Diagram Placeholder 协议

当接收来自 `fsd-writer` 的占位符块（`[VISUAL-PLACEHOLDER | ID: ... | TYPE: diagram | LANG: ...]`）时：
1. **严格读取 `LANG` 字段**：英文文档产出全英文图表，中文文档产出全中文图表，术语与正文表格保持 100% 一致。
2. **禁止增删业务事实**：只可视化 FSD 正文中已确认的节点、状态名、时间数值和分支条件；若发现正文里某条分支没写清，向用户反馈或标出疑问，不要在图里擅自编造规则。
3. **保留标准图注**：出图回填时保留 Placeholder 中指定的 `回填图注`（如 `Figure: ...`）。
